# Architecture Checklist

- [ ] Current architecture and accepted ADRs read
- [ ] Concrete, present need stated (not "best practice" alone)
- [ ] At least two options evaluated, including "keep current approach"
- [ ] Fit with existing module boundaries and conventions assessed
- [ ] Interfaces/contracts defined (shapes, errors, versioning)
- [ ] Backward compatibility assessed; breaking changes have migration/deprecation plan
- [ ] Data model impact and migrations identified (→ `database-engineer`)
- [ ] Security impact assessed (trust boundaries, authn/authz)
- [ ] Operational impact (deployment, monitoring, cost) assessed
- [ ] Reversibility assessed; irreversible parts flagged
- [ ] Negative consequences listed
- [ ] ADR written with status `Proposed`; human decision requested
